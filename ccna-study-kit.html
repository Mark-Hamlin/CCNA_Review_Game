Packet Tracer lab scenarios

Built for Cisco Packet Tracer 8.x. Each lab lists its topology, addressing, tasks and verification commands. Try the tasks first, then open the solution configs to compare.

  • Device models: routers 2911, switches 2960-24TT, Layer 3 switch 3650-24PS, PC-PT, Server-PT. Lab 11 adds a WLC-3504, 3702i lightweight APs, a 3560-24PS PoE switch and Laptop-PT.

LAB 01

Secure device baseline and SSH

Exam topics 4.8, 5.3 · Basic IOS configuration, passwords, banners, SSH · ~45 min

Scenario. A new branch router and access switch arrived from the warehouse with factory defaults. Before they go into production you must harden them so that only an authorized administrator can manage them, and only over SSH.

Topology

  PC1 ──Fa0/1─[ S1 2960 ]─Gi0/1──────G0/0─[ R1 2911 ]
   └───── console cable (RS-232 → R1 Console), optional
DeviceInterfaceIP address / prefixDefault gateway
R1G0/0192.168.1.1 /24–
S1VLAN 1192.168.1.2 /24192.168.1.1
PC1NIC192.168.1.10 /24192.168.1.1

Tasks

  1. Build and cable the topology. Set PC1's IP settings (Desktop › IP Configuration).
  2. On both devices: set the hostname, disable DNS lookup of mistyped commands (no ip domain-lookup), and set an enable secret.
  3. On R1, require a 10-character minimum for passwords configured from now on (do this before setting R1's passwords).
  4. Secure the console line with a password, logging synchronous and a 5-minute exec timeout.
  5. Encrypt plain-text passwords in the config, and add a MOTD banner warning against unauthorized access.
  6. On R1, block logins for 120 seconds after 3 failed attempts within 60 seconds.
  7. Configure SSH version 2: domain name ccna.lab, local user admin, 1024-bit RSA keys. VTY lines must use local login and accept SSH only (R1 lines 0–4, S1 lines 0–15).
  8. Address R1 G0/0 and the S1 management SVI, and give S1 a default gateway.
  9. Administratively shut down every unused switch port on S1.
  10. Save the configurations.

Verify

  • From PC1 Command Prompt: ssh -l admin 192.168.1.1 and ssh -l admin 192.168.1.2 succeed. telnet 192.168.1.1 is refused.
  • show ip ssh reports SSH enabled, version 2.0.
  • show running-config shows no clear-text passwords (console password appears as type 7).
  • show ip interface brief on S1: Fa0/2–24 and Gi0/2 are "administratively down".
Packet Tracer prompts How many bits in the modulus [512]: after crypto key generate rsa. Enter 1024. SSH version 2 needs a key of at least 768 bits.

VLANs and 802.1Q trunking

Exam topics 2.1, 2.2, 2.3 · VLANs, access ports, trunks, native VLAN, DTP, CDP · ~40 min

Scenario. Sales and Engineering share two access switches on the same floor. Separate them into their own VLANs, carry both VLANs between the switches on a trunk, and move switch management off VLAN 1.

Topology

      Fa0/6          Fa0/11                     Fa0/6          Fa0/11

VLANNameUse

999NATIVETrunk native VLAN (no hosts)
DeviceInterfaceIP address / prefixVLAN

S2VLAN 99192.168.99.12 /2499

PC2NIC192.168.20.12 /2420
PC3NIC192.168.10.13 /2410

Tasks

  1. Cable the topology (S1–S2 with a cross-over cable) and address the PCs. There is no router, so leave the PC gateways blank.
  2. Create VLANs 10, 20, 99 and 999 with the names shown on both switches.
  3. Make Fa0/6 and Fa0/11 static access ports in the correct VLANs.
  4. Make Gi0/1 a static trunk: native VLAN 999, allowed VLANs 10, 20, 99, 999, and DTP disabled.
  5. Configure the VLAN 99 management SVI on each switch.
  6. Break and fix: change S2's native VLAN back to 1, wait for the CDP native VLAN mismatch message on the console, then fix it.

  • show interfaces g0/1 switchport: Negotiation of Trunking: Off.
  • PC1 pings PC3 and PC2 pings PC4. PC1 cannot ping PC2: they are in different VLANs and subnets with no router (that's Lab 3).
  • S1 pings S2 at 192.168.99.12.

LAB 04

Rapid PVST+ root placement and edge protection

Exam topic 2.5 · Root bridge election, port roles, load sharing per VLAN, PortFast, BPDU Guard · ~50 min

Scenario. Three distribution switches are cabled in a triangle for redundancy. Spanning tree picked a root on its own, based on the lowest MAC address. You will control root placement so VLAN 10 and VLAN 20 use different links, speed up convergence, and stop users from plugging rogue switches into access ports.

Topology

                    [ S1 2960 ]
                  Gi0/1     Gi0/2
                  /             \
              Gi0/1             Gi0/1
         [ S2 2960 ]─Gi0/2───Gi0/2─[ S3 2960 ]
          Fa0/6  Fa0/11            Fa0/6  Fa0/11
          PC1    PC3               PC2    PC4
        VLAN 10  VLAN 20         VLAN 10  VLAN 20
DevicePortIP address / prefixVLAN
PC1S2 Fa0/6192.168.10.21 /2410
PC2S3 Fa0/6192.168.10.22 /2410
PC3S2 Fa0/11192.168.20.23 /2420
PC4S3 Fa0/11192.168.20.24 /2420

Tasks

  1. Cable the triangle with cross-over cables. On all switches create VLANs 10 and 20 and make Gi0/1 and Gi0/2 trunks. Set the access ports.
  2. Before changing STP, run show spanning-tree vlan 10 on every switch. Record the root bridge, each root port, and the port in the ALTN/BLK (or BLK) role. Explain why that switch became root.
  3. Change all three switches to Rapid PVST+.
  4. Make S1 the primary root for VLAN 10 and secondary for VLAN 20. Make S2 the primary root for VLAN 20 and secondary for VLAN 10.
  5. Predict which S3 port blocks in each VLAN, then check. (Expected: VLAN 10 blocks S3 Gi0/2; VLAN 20 blocks S3 Gi0/1.)
  6. Enable PortFast and BPDU Guard on all access ports. Also configure S2 Fa0/24 as an access port in VLAN 10 with PortFast and BPDU Guard.
  7. Test BPDU Guard: connect a new 2960 to S2 Fa0/24. The port should go err-disabled. Remove the switch, then recover the port with shutdown / no shutdown.
  8. Test convergence: start ping -t 192.168.10.22 on PC1, then shut S3 Gi0/1. Watch S3's alternate port become the root port for VLAN 10.

Verify

  • show spanning-tree vlan 10 on S1: "This bridge is the root", priority 24586 (24576 + VLAN 10).
  • show spanning-tree vlan 20 on S2: "This bridge is the root", priority 24596.
  • show spanning-tree summary: mode rapid-pvst.
  • show running-config lists spanning-tree portfast and spanning-tree bpduguard enable on each access port. A PC's link turns green right away instead of waiting about 30 seconds.
  • After the BPDU test, show interfaces fa0/24 on S2 reports err-disabled, and a %SPANTREE-2-BLOCK_BPDUGUARD log message appears.
Why S3 blocks different ports: in VLAN 10, S2 (priority 28682) has a lower bridge ID than S3 (32778), so S2's Gi0/2 wins the S2–S3 segment as designated and S3's Gi0/2 becomes alternate. In VLAN 20 the same logic makes S1 win the S1–S3 segment.

LAB 05

EtherChannel with LACP and PAgP

Exam topic 2.4 · Layer 2 EtherChannel, LACP active/passive, PAgP desirable/auto · ~40 min

Scenario. The uplinks from the core switch S1 are congested, and spanning tree is blocking half the cables you installed. Bundle the parallel links into EtherChannels so all of them carry traffic and STP treats each bundle as one logical link.

Topology

            Fa0/1 ══════ Fa0/1
   [ S1 ]   Fa0/2 ══════ Fa0/2   [ S2 ]── Fa0/10 PC1 (VLAN 10)
     ║       Po1 (LACP)             │
     ║ Fa0/3 ═══ Fa0/3              │ Gi0/1
     ║ Fa0/4 ═══ Fa0/4              │ (regular trunk)
     ║  Po2 (PAgP)                  │ Gi0/1
     ╚═══════════════════════[ S3 ]─┘── Fa0/10 PC2 (VLAN 10)
DeviceInterfaceIP address / prefixVLAN
S1VLAN 99192.168.99.1 /2499
S2VLAN 99192.168.99.2 /2499
S3VLAN 99192.168.99.3 /2499
PC1S2 Fa0/10192.168.10.11 /2410
PC2S3 Fa0/10192.168.10.12 /2410

Tasks

  1. Cable the topology. Before configuring anything, notice that STP blocks one link of each parallel pair (amber link lights).
  2. Create VLANs 10 and 99 on all switches; configure PC ports as access ports in VLAN 10.
  3. Bundle S1–S2 Fa0/1–2 into Port-channel 1 using LACP (S1 active, S2 passive).
  4. Bundle S1–S3 Fa0/3–4 into Port-channel 2 using PAgP (S1 desirable, S3 auto).
  5. Make both port-channels and the S2–S3 Gi0/1 link trunks allowing VLANs 10 and 99 only.
  6. Configure the VLAN 99 SVIs.
  7. Break and fix: change S1's Po1 members to channel-group 1 mode passive. Explain why the bundle drops, then restore it.

Verify

  • show etherchannel summary: Po1(SU) with protocol LACP and Po2(SU) with PAgP; member ports flagged (P).
  • show interfaces trunk lists Po1 and Po2 instead of the physical ports.
  • show spanning-tree shows Po1 and Po2 as single ports.
  • PC1 pings PC2, and the switches ping each other on 192.168.99.0/24.
If a bundle stays down after you fix a mismatch, shut and re-enable its member ports (interface range fa0/1 - 2, shutdown, no shutdown) on both switches.

If your Packet Tracer version won't pass client traffic on the VLAN 30 dynamic interface, map the WLAN to the management interface instead (General tab). Clients then get 192.168.99.x addresses. The lab still works, but user and management traffic share a subnet, which you wouldn't do in production.

Option 43: f1 is the type, 04 the length (4 bytes per controller), and c0a8630a is 192.168.99.10 in hex (c0 = 192, a8 = 168, 63 = 99, 0a = 10).

GUI answers: the default QoS profile is Silver (best effort). Use Platinum for voice; Gold is for video and Bronze for background traffic. Allow AAA Override lets a RADIUS server assign per-user settings such as the VLAN or ACL. FlexConnect Local Switching lets a FlexConnect AP switch client traffic onto its local wired network instead of tunneling it to the WLC.

Why the APs use access ports: in Local mode, client traffic is tunneled to the WLC inside CAPWAP, so the AP needs only its management VLAN. The WLC uplink is a trunk because the WLC hands client traffic to the wired network on VLAN 30. A FlexConnect AP doing local switching would need a trunk instead. To bundle several WLC ports with LAG, the switch side must use EtherChannel mode on, since the WLC doesn't negotiate LACP or PAgP.
